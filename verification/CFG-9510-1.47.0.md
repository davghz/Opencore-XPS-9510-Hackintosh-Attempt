## Adaptation and tests

Based on `davghz/hackintosh` commit
`2ac346e4c2ba7745e58c1ad049838b4b2227631b` and XPS repository commit `6193d51`.
The port changes the HP identity, payload length and arm token to the verified
Dell values, adds a system-model guard, and checks that existing Driver entries
and Boot variables survive installation/cleanup. The read-only checker requires
all online CPUs rather than trusting only the devices visible in `/dev/cpu`.

Fourteen Python tests passed: profile acceptance/refusal, already-unlocked
refusal before installation mutations, malformed data, online CPU enumeration,
incomplete reads, mixed lock states, firmware/hardware disagreement, and cleanup
preserving an existing Driver0000 and BootOrder while refusing a changed entry.

The C code compiled with `-Wall -Wextra -Werror` using GNU-EFI 3.0.15 and GCC.
QEMU 8.2.2 / OVMF passed these 12 cases using a synthetic locked baseline:

1. Exactly one write changing only byte 0x43 across all 654 bytes.
2. One-shot token prevents a second write.
3. Firmware write protection leaves the variable unchanged.
4. Baseline mismatch prevents a write.
5. Attribute mismatch prevents a write.
6. Already-disabled setting prevents a write even if rearmed.
7. Wrong system model prevents a write.
8. Wrong board prevents a write.
9. Wrong BIOS version prevents a write.
10. Wrong BIOS date prevents a write.
11. Missing SMBIOS identity prevents a write.
12. Unarmed invocation prevents a write.

The test also verified the result log persisted to the virtual FAT filesystem.
The inherited fixture's GUID comparison was changed to an explicit byte
comparison so write tracking works across GNU-EFI versions.
